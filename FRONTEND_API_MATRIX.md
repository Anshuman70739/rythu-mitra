# Frontend-to-backend API matrix — Master Backend v1

All requests are same-origin; write methods send `X-CSRF-Token` from `GET /api/session`. The frontend does not write owner/role/moderation/source-provenance fields. Optional fields are only rendered from actual responses. “Implemented in UI” is not the same as provider/model-backed integration being operational.

| Screen/workflow | Request | Request fields / query | Response fields consumed | Authentication and limits |
|---|---|---|---|---|
| Bootstrap/session | `GET /api/session` | none | `success`, `user`, `csrf_token`, `demo_mode` | Public session lookup |
| Register | `POST /api/register` JSON | `name`, `phone`, `password`, optional `role` (`farmer`/`buyer`), `language` | `user`, `csrf_token` | CSRF; phone 8–15 digits; password ≥8; no OTP |
| Login/logout | `POST /api/login`; `POST /api/logout` JSON | login: `phone`, `password`; logout `{}` | `user`, refreshed `csrf_token` | CSRF; hashed-password backend; login rate limit |
| Profile/settings | `POST /api/profile` JSON | `name`, `language`, `district`, `mandal`, `village`, `land_area`, `soil_type`, `irrigation`, `current_crop`, `crop_stage`, `previous_crop`, `season`, `budget`, `experience` | updated `user` | Auth + CSRF |
| Today dashboard | `GET /api/dashboard` | none | `profile`, `weather`, `actions`, `crop_calendar`, `notifications`, `market`, `recent_history`, `seed_alerts`, `seed_expiry_alerts`, `inventory_alerts`, `finance_summary`, `data_status` | Auth farmer/expert/admin/buyer/provider; this is a partial dashboard, not a field-validated action engine |
| Family dashboard | `GET /api/family-dashboard` | none | `success` and scoped dashboard fields | Farmer role; backend scopes determine visibility |
| Weather | `GET /api/weather?city=...` | `city`, optional `refresh=1` | success/error, `status`, `data_type`, temperature/humidity/rainfall/rain probability/wind, forecast/advisories, cache/source timestamps if supplied | Public read; key/provider required for live data; unavailable returns 503 |
| Crop recommendation | `POST /api/recommendations` JSON | `N`, `P`, `K`, `temperature`, `humidity`, `ph`, `rainfall` | `crop`, `model_version`, `model_confidence` when valid, `plan`, `simple_reference_nutrient_check`, `reasoning`, `disclaimer`, status/type | CSRF; crop model artifact required; input values validated |
| Yield reference | `POST /api/yield-estimate` JSON | `ph`, `temperature`, `rainfall` | `reference_favorability_score`, `score_type`, `status`, note/disclaimer | CSRF; reference rule score only, not yield quantity |
| Crop risk | `POST /api/crop-risk` JSON | `crop`, optional `crop_stage`, `humidity`, `rain_probability`, `wind_kmh`, `nearby_pest_reports` | score/factors, status, explanation and disclaimer (fields depend on route output) | CSRF; farmer/expert/admin; heuristic/rule-based, not validated prediction |
| Irrigation advice | `POST /api/irrigation-advice` JSON | crop, crop stage and supplied rainfall/moisture/irrigation fields | status, guidance/factors and limitations | CSRF; uses only passed inputs; not a validated agronomic model |
| Crop tasks, plots, diary, soil, inputs, finance, livestock, etc. | `GET /api/v1/<slug>?limit=50&offset=0&q=...`; `POST /api/v1/<slug>`; detail GET/PATCH/DELETE | JSON keys are restricted by the exact field allowlist and required list in `static/data/resource-config.json`; array/object inputs require JSON syntax | `records`, `count`, `limit`, `offset`, `data_type`; write returns saved record/message; delete is soft delete where supported | Read auth/public-read rules and create role from backend `RESOURCE_SPECS`; write CSRF/auth; never submit protected keys |
| Crop Health scan | `POST /api/disease-scan` multipart | file field `image` (JPEG/PNG/WebP) | `result`, `confidence` if valid, `low_confidence`, `label_verified`, `model_version`, `guidance`, `scan_id`, status/type, notes | CSRF; rate limited; model bundle required for successful prediction; anonymous scan is temporary |
| Scan history | `GET /api/scan-history?limit=30`; `POST /api/scan-history` JSON `{scan_id}`; `DELETE /api/scan-history/<scan_id>` | current user-owned scans or anonymous scan linked to same session | `records` including `expert_reviews`; write returns linked record; delete confirmation | Auth for history/save/delete; CSRF on writes |
| Expert review of scan | `POST /api/disease-scans/<scan_id>/expert-review` JSON | `question_id`, `assessment`, `review_notes`, optional `recommended_next_step`, `follow_up_required` | `record`, note | Expert role + CSRF; specialized UI attachment/consent flow remains follow-up |
| Seed evidence capture | `POST /api/seed/scans` multipart | images: `front_packet`, `back_packet`, `certification_tag`, `qr_label`, `receipt`; optional confirmed/manual fields (`crop`, `variety`, `brand`, lot/batch, dates, label metrics, `qr_content`, `farm_id`) | `record`, `uploads`, OCR text/candidates, review-required fields, upload errors, warning | Farmer + CSRF; private files; OCR optional; OCR candidates are not automatically confirmed |
| Confirm seed data | `POST /api/seed/scans/<scan_id>/confirm` JSON | `{confirmation:true, confirmed_fields:{...}}`; field names validated by backend | updated `scan`, created `seed_lot`, message | Owner farmer + CSRF; confirmation says only the entered fields were checked, not authenticity |
| Seed QR decoding/check | `POST /api/seed/qr-decode` multipart `image`; `POST /api/seed/qr-check` JSON `qr_content`, optional `lot_number`, `brand` | uploaded code image or printed text for comparison | codes, format, visible safe HTTPS destination, domain trust boolean, comparison, mismatch/unverified status | Farmer for decode; farmer/expert/admin for manual check; pyzbar/zbar optional; destination is not fetched |
| Seed packet completeness | `POST /api/seed/packet-check` JSON | packet-label fields such as crop, variety, brand, lot, packing/validity, germination, MRP | completeness checklist, `verification_status=UNVERIFIED`, next steps | CSRF; checks label completeness only |
| Germination screen | `POST /api/seed/germination` JSON | `tested_count`, `germinated_count`, `test_date`; optional `test_method`, `seed_lot_id`, `label_germination_pct`, `notes` | saved record, `germination_percentage`, informal home-screening disclaimer | Farmer + CSRF; whole counts; not official certification |
| Seed complaint & escalation | `POST /api/seed/complaints` JSON; `GET /api/seed/escalation` | `complaint_type`, `description`, optional lot/crop/purchase/sowing/location/area/evidence fields | `record`, complaint number, `official_submission.submitted=false`; escalation returns verified official links with caveat | Farmer + CSRF for complaint; complaint stays in-app |
| Markets | `GET /api/markets?commodity=...&district=...`; provider call via `provider=live`; `GET /api/markets/trend?commodity=...&market=...` | commodity, district, market | `records` with prices, `price_date`, source/type/updated/verified, `is_stale`, note | Public read; official data.gov.in/AGMARKNET daily connector uses server-side `DATA_GOV_IN_API_KEY`; daily rows use `LATEST_REPORTED`, while missing key/provider/records return `UNAVAILABLE` |
| Economics | `POST /api/market-net-income` JSON `quantity`, `price`, optional `transport`, `charges`, `storage_cost`, `other_costs`; `POST /api/storage-calculation` JSON quantity/days/daily storage/sell-now/future scenario/transport/charges/spoilage; `POST /api/finance/break-even` JSON `total_costs`, `expected_quantity`, optional `unit`, `expected_price` | all values user-entered; front-end sends numeric inputs | calculated values, `status=CALCULATED`, `data_type=USER_ENTERED_CALCULATION`, disclaimer | CSRF; break-even also requires auth; future price is not a prediction |
| Scheme matcher | `GET /api/schemes/matches` | profile is sourced from server session | `matches` and match statuses, official links/source metadata where supplied | Eligibility is only a possible match; external application is not submitted |
| Notifications | `GET /api/notifications`; `POST /api/notifications/<id>/read` | read marker has no caller-selected owner | `records`, read confirmation | Auth; write CSRF; in-app only |
| Offline sync | `POST /api/offline/sync` JSON `{operations:[{operation_id, resource, payload}]}` | 1–25 operations; resource restricted to backend allowlist | per-operation `success`, `status=SYNCED/REJECTED/FAILED`, stable ID and optional record | Farmer + CSRF; client removes/keeps only on explicit backend status |
| Private evidence upload | `POST /api/v1/uploads` multipart `image`, `category` | allowlisted upload category | private upload ID and metadata | Auth+CSRF; authorized owner retrieval only via `/api/v1/uploads/<id>` |
| Admin | `/api/admin/summary`, `/api/admin/users`, `PATCH /api/admin/users/<id>`, `/api/admin/data-health`, `/api/admin/audit-logs`, `/api/admin/notifications`, `/api/admin/resources/<resource>/<id>/moderate`, `/api/admin/market-prices/import-csv`, `/health`, `/ready` | uses each route's own schema; CSV import is an admin-managed draft action | summaries, audit rows, freshness diagnostics, outcomes/errors | Admin permissions server-side; no external SMS/provider or official submit is implied |

## Generic resource groups

The shipped `resource-config.json` is extracted from the exact backend allowlists. Resource groups in navigation include:

- Farms/plots: `farms`, `farm-plots`
- Planning/diary/calendar: `crop-plans`, `crop-tasks`, `farm-diary`, `farm-observations`, `crop-rotation-plans`, `intercropping-plans`, `harvest-plans`
- Soil/inputs/water: `soil-records`, `input-purchases`, `inventory-items`, `input-products`, `water-sources`, `irrigation-records`, `irrigation-plans`, `rainwater-plans`
- Seeds: `seed-lots`, `seed-scans`, `seed-test-results`, `seed-complaints`, `seed-complaint-events`
- Market/schemes/finance: `market-prices`, `market-sources`, `schemes`, `scheme-documents`, `scheme-tracking`, `benefit-tracking`, `expenses`, `income`, `loans`, `labour-plans`
- Livestock/harvest/services: `livestock`, `livestock-health`, `dairy-records`, `fish-ponds`, `livestock-fish-records`, `harvest-records`, `produce-quality`, `drying-records`, `storage-facilities`, `storage-bookings`, `equipment-listings`, `equipment-bookings`, `service-directory`
- Marketplaces/community/support: `farmer-listings`, `buyer-requests`, `expert-questions`, `expert-answers`, `expert-votes`, `crop-damage-reports`, `complaints`, `insurance-records`, `insurance-claims`, `community-posts`, `market-feedback`, `fpo-directory`, `fpo-groups`, `pest-reports`, `notices`, `family-helpers`, `crop-risk-reports`, `harvest-plans`, `offline-drafts`, `local-alerts`, `source-records`, `content-reports`, `disease-knowledge`, `disease-reviews`.
